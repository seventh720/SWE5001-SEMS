# 公共目录 JDBC 读取候选（本地验证，未部署）

日期：2026-10-22（新加坡时间）。基线为已部署 PR #22 / `1413622` 的应用代码；本地基线镜像来自同一读取源码 `fd925bd`。本轮只做一组候选对照，以便在24日下午展示前控制投入。当前线上应用和默认连接池10均未修改。

## 改动

公共目录的组织发现、分页/必要总数查询、详情改用参数化 JDBC 字段读取，减少 Hibernate 查询构造与完整实体映射。写入、事务锁和内部详情仍使用原 JPA 实现。列表继续先实时校验组织状态再分页，详情的私有活动权限、13字段响应、时间与分类筛选保持原规则；搜索显式保留原 JPQL 对反斜杠的字面匹配语义。

## 验证

`mvn verify` 83项、Checkstyle和构建通过。真实 PostgreSQL/HTTP 的目录读取、可见性、组织目录协作与数据库隔离四项验收全部通过。新增反斜杠回归同时在基线和候选上通过；现有检查覆盖满页/末页/越界页总数、分类、私有活动、暂停即时生效、公开字段、当前组织名及历史详情。前端未修改，本轮未单独重跑前端测试。

## 一组本地对照

250个真实账号、100场负载活动、每人一笔固定的取消订单；另有API验收数据，均在正式测量前建立，不匹配负载关键字。两轮只读、数据相同，每轮重建Catalog。先50 VU爬升30秒/保持30秒预热，再250 VU爬升30秒/保持60秒，沿用原四请求/1秒思考模型和阈值，基线先、候选后。

资源固定：Catalog 0.8、Identity 0.4、Admission 0.4、PostgreSQL 0.3、网关0.09、Web 0.01 CPU，总计2；三个Java服务各768 MiB、Xmx384 MiB，池10。只在不计分的造数阶段临时给Identity 2 CPU，验收前恢复0.4；正式每轮核对实际CPU配置。两个Catalog镜像的JRE基础层相同。生成器为k6 1.3.0、4 CPU/2 GiB，访问本机HTTP。

这组整体p95低约18.3%，吞吐高约5.0%，四类接口p95均下降；据此保留候选供PR/部署复验。两轮均达到250 VU并完成60秒保持，原阈值通过、健康保护未触发。网关5xx覆盖每轮预热至250阶段结束，未发现内部超时或连接额度告警。分接口结果、同实例累计计时差值、镜像和源码校验见[精简汇总](summary.json)；计时均值覆盖250阶段的爬升/保持/收尾，与请求保持期p95口径不同，Hikari和读取计时互相重叠。

**这是一组短时本地观察，尚未证明稳定提升或云端容量。** 未交错重复，不能排除时间/JIT波动；固定配额与本机HTTP也不同于云端共享双核调度。没有执行500/1000 VU或十分钟稳态，不把本次结果写成这些目标通过。
