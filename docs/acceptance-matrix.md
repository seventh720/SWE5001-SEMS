# 能力与验收矩阵

生产环境采用两节点 EC2 K3s，业务位于 `sems-prod`，监控位于 `observability`。代码和部署检查见 [main CI/CD](https://github.com/seventh720/SWE5001-SEMS/actions/workflows/ci.yml?query=branch%3Amain)，实测结果见[证据索引](evidence/README.md)。

| 能力 | 验证范围 | 边界与限制 |
| --- | --- | --- |
| 多组织业务 | 组织治理、成员角色、跨组织拒绝、活动与成员组合筛选、总览口径 | 不包含企业 SSO/层级组织；节省工时未量化 |
| API 与数据边界 | 独立 API/schema/账号/迁移、跨 schema 拒绝、内部令牌与公网路径拒绝 | 自动 OpenAPI 符合性未接入 |
| 报名闭环 | 注册、授权、发布、报名、出票、核销、统计、预约、通知与取消 | API、浏览器和设备结果分别记录 |
| 并发与幂等 | 两个 Admission 实例竞争 10 名额、同键重放/异载荷、重复核销与取消竞争；当前版本另测 100 人抢 10 名额，恰好 10 成功/90 售罄且 SQL 一致 | 正确性不代表吞吐提升 |
| 权限与会话 | JWT、实时成员/平台角色撤权、本人订单、工作人员分配、认证限流 | 当前网关限流不是分布式配额 |
| 副本与调度 | 五个应用各两个就绪副本且跨节点；独立副本调整与 Pod 重建 | 第三个同服务副本需要更多节点或不同测试拓扑；未启用 HPA |
| 故障恢复 | 当前版本分别删除 Catalog / Admission 一个 Pod；25 VU 加持续订票/重放/回执，业务恢复目标与订单留存通过；保留瞬态错误和替换 Pod 就绪时间 | 各一次样本；单 Pod 结果不说明主机、控制平面或数据库 HA |
| 容量与扩容收益 | [当前 K3s 实测](evidence/2026-11-06-cloud-validation/README.md)：100 VU 混合十分钟通过；Catalog 25/50/100 VU、Admission 25/50 VU 的 1/2 副本对照 | 每个条件仅一个样本；Admission 100 VU 单副本预热内部 504，严格门禁失败，双副本未执行；尚无最大容量结论 |
| 安全交付 | HTTPS、扫描、同次 image lock、main-only OIDC/SSM 发布和发布后验证 | [限定依赖例外](security.md)按有效期管理；扫描不替代权限验收 |
| 数据与回退 | 27 表/角色/凭据一致、Retain PV、发布前备份、兼容镜像回退和临时库恢复 | 数据库为单实例，无周期异地备份、PITR 或自动切换 |
| 可观测性 | 两节点/Pod/控制平面/数据库/公网指标、日志、三服务追踪、Grafana 登录及 Telegram 触发/恢复 | 栈内监控单实例，无独立于集群的外部故障探测 |

[测试说明](test-coverage.md)解释覆盖边界，[扩容实验](performance-and-availability.md)定义对照方法。验证结论附有版本、环境、参数和失败结果。
