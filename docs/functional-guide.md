# 当前功能与业务规则

截至 2026-10-17；接口字段以 `contracts/*.openapi.json` 为准。

## 组织、活动与工作人员

平台 ADMIN 创建组织并指定首位组织管理员，可修改组织名称／地址、审核变更及注销申请，并直接软删除。组织管理员可提出申请；注销通过后组织设为 SUSPENDED，成员权限撤销，个人历史订单与票券保留。软删除为 DELETED，不再出现在正常列表。组织角色为 ORG_ADMIN、ORGANIZER、MEMBER；旧全局 ORGANIZER/STAFF 不再授予业务权限。组织管理员管理成员和邀请，组织管理员与组织者管理本组织活动、报名列表和工作人员。平台 ADMIN 不自动取得组织业务权限。成员资格实时校验。

PUBLIC 活动进入公共目录；ORGANIZATION_ONLY 活动仅有效成员可发现和新报名。已有票券权益不因移除成员或更改可见性自动失效。工作人员按活动分配，必须为有效成员；支持浏览器摄像头、手动票码或键盘式扫码器输入。手机优先后置摄像头，PC 可选内置/USB 摄像头；识别后自动提交一次并关闭摄像头，点击 Scan next ticket 后继续。拒绝权限、无摄像头或非安全连接时可改用票码；手机访问需 HTTPS，电脑 localhost 可本地验证。扫码图像仅在浏览器内解码，不上传视频。

目录支持标题搜索和分类筛选；分类与卡片主题独立。统一编辑器保存详情、日期、容量、票种及销售窗口；首次发布后报名字段固定。暂停隐藏活动并阻止新报名，但保留已有票券。整场取消与暂停独立：组织管理员或活动组织者在 Publication management 点击 Cancel entire event，填写原因并确认。Catalog 先记录 CANCELLING 并停止公开展示/新报名资格；Admission 原子撤销确认订单和未使用票券，保留已签到历史，发出站内通知，随后 Catalog 进入不可恢复发布的 CANCELLED。取消与编辑/发布不能同时进行，必须等待已有操作结束。改期、配额和恢复协议见 [发布管理](publication-management.md)及[改期规则](schedule-revision.md)。

## 预订、票券与统计

仅免费票；每单一个票种、1–10 个名额、一份报名联系人。可售量为 quota − reserved；confirmed 数量计入 reserved。同一事务创建订单和每名额独立票券。

同用户/request key 通过数据库 advisory lock、唯一约束和 sales 行锁保证幂等；同键同参数返回原订单，异参数返回 409。远程资格校验在本地事务前，事务内再次检查销售状态、时间与名额。前端在不确定失败后保留请求键和原始资料，刷新后仍可重试。取消订单不因重放创建请求而复活。

订单 CONFIRMED → CANCELLED；票券 VALID → CHECKED_IN 或 CANCELLED。参与者仅可在活动开始前且整单无已签到票时取消，库存至多归还一次。签到在当前活动开始前 15 分钟开放（含边界），提前返回 409；服务端持有 sales 行锁后按数据库时间校验。签到与取消使用同一 sales 行锁，重复核销返回原结果且不增加人数。整场取消后确认票数和可报名名额均为 0，出席人数作为历史记录保留；暂停不撤销票券。组织者 summary API 返回销售状态、确认票数、可售名额和出席人数（字段见契约）。

二维码由本地 node-qrcode 生成，内容为每张票独立的 192-bit 十六进制凭证；手动码使用同一凭证。取消票不展示有效票码。个人订单仅本人可访问；组织报名列表不返回票码，私有接口禁止缓存。

## 报名资料、联系人及预约

活动可要求姓名、邮箱、电话、学号、护照号和一个自定义回答。服务端拒绝未要求的字段并校验必填项；幂等比较包含标准化资料。历史订单保留联系人及票种名等快照。

My profile 支持用户名及多份有名称的联系人；报名时手动选择 Apply saved details，再核对本活动要求。通用联系人不保存学号或自定义回答。

开售前可保存预约，每用户每活动一份，不占库存，也不自动出票。开售后必须手动确认，重新校验资格和名额；成功报名同事务移除对应预约。删除预约不取消订单。Dashboard 展示近期订单、预约及公共活动，My tickets 分已确认与已取消列表。

显示和输入时间统一为新加坡时间 UTC+08:00，后端存 UTC。倒计时仅提示，实际销售资格由服务端决定。站内邀请、事件变化及开售提醒见[站内通知](in-app-notifications.md)。未实现中英文切换、深浅色切换、外部邮件或短信。

## 数据升级和验证

早期迁移包括 Admission V3（订单/票券）、Catalog V3 / Admission V4（报名资料）、Identity V2 / Admission V5（资料/预约）、Identity V3（多联系人）。保留全部 Flyway 历史，旧数据库通过追加迁移升级。不得在要求报名资料的新活动上运行不验证这些字段的旧 Admission；有订单后也不能直接恢复旧库存写入程序。

已有环境的组织升级必须按[维护迁移说明](organization-upgrade.md)执行；通知迁移见[通知说明](in-app-notifications.md)。镜像回滚不撤销数据库迁移。

验收入口与运行限制见 [CI](ci.md)。保留所有 `scripts/*acceptance.py`：较新的脚本会复用旧脚本，它们是可执行回归资产。历史实测保留在 `docs/evidence/`，不等同于当前版本或云环境的重新验收。

## 上线前修正后的规则

平台超管接口同时检查 JWT 声明和数据库当前角色；降权后旧令牌的后续管理请求立即拒绝。组织成员权限仍由实时成员关系决定。

永久注销/软删除先进入 CLOSING，自动取消申请时尚未结束的活动，撤销未使用票券并通知所有相关参与者；完成后才撤销成员/邀请并进入 SUSPENDED 或 DELETED。故障时保留关闭中并自动恢复。历史订单与已签到记录保留，普通临时暂停组织仍可恢复；永久关闭不能激活。

成员目录、组织预览和签到员工选择使用服务端分页查询。支持用户名/邮箱搜索，页面切换保留已保存的员工分配；分页接口返回 items 和总数，不再返回全量数组。组织预览每次三人，完整目录和员工选择每页十二人。
